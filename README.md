<br/>

<a href="https://github.com/thedeepakreddy/Prescriptive-Churn-Analytics-in-E-commerce"><img src="https://img.shields.io/badge/Source_Code-181717?style=for-the-badge&logo=github&logoColor=white"/></a>

> **Most churn models answer "who will leave?" This one answers "who is worth saving, and what should we do about it today?"**

| | Result |
|:---|:---|
| **Model** | **ROC-AUC 0.9248** · recall **0.79** · precision **0.88** on the churn class |
| **Business impact** | **$1.51M** net retention profit on a 10,000-customer test cohort |
| **Key decision** | Threshold moved from `0.50` to **`0.28`**, chosen by **profit, not accuracy** |
| **Data** | 50,000 customers · 24 features · 28.9% churn · real-world missingness |
| **Delivery** | Streamlit action app plus Tableau executive dashboard — a prioritised daily call list, not a notebook |

**Why the threshold move matters.** A default `0.50` cutoff silently assumes that a lost \$50 bargain hunter costs the same as a lost \$5,000 loyalist. Missing a churner costs their **entire lifetime value**; a wasted coupon costs only the **margin on the discount**, roughly 15%. Missing a churner is therefore about **7x more expensive**, so any threshold tuned for accuracy or F1 is leaving money on the table *by construction*.

```python
tp_profit = ((LTV - cost) * SUCCESS_RATE).sum()   # saved, minus the discount
fp_loss   = -cost.sum()                           # wasted discount only
fn_loss   = -LTV.sum()                            # the expensive mistake
net_profit = tp_profit + fp_loss + fn_loss        # curve peaks at 0.28
```

**Engineering rigour.** Split first, transform second — all imputation and scaling live inside a `ColumnTransformer` fit **only** on training data, so no test-set statistics leak backwards. `KNNImputer` (k=5) is applied *after* scaling, since unscaled KNN imputation is silently dominated by whichever column has the largest units. Class imbalance is handled by `class_weight='balanced'` re-weighting rather than injecting SMOTE noise into a 40k-row training set.

| Finding | Number |
|:---|:---|
| Orders audited | **9,964** |

3. **Weather is a controllable cost.** Snow raises breach risk 5.2x, so it belongs in the dispatch buffer rather than in an excuse.

Two people, two languages, one push-to-talk button. Audio is captured through `MediaRecorder`, transcribed with ElevenLabs `scribe_v1`, translated, and re-synthesised in the receiver's language with `eleven_multilingual_v2` — in near real time.

- **WebRTC data channels** carry the translated text peer-to-peer, so no central server routes the conversation
- **QR-code handshake** for instant session joining, with no link-sharing friction
- **Custom WebSocket signaling server** negotiating SDP offers, answers and ICE candidates
- **Graceful degradation** from ElevenLabs TTS to the browser's native `SpeechSynthesis` if network requests drop, so a call never goes silent
- **API keys never reach the client** — Express strictly proxies `/api/tts` and `/api/stt`
